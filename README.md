# green-button

Скрипт принимает имя пакета Android-приложения, запускает его на телефоне, подключённом через `adb`,
находит на экране зелёную кнопку и нажимает на неё. Если за 10 секунд кнопка не появилась, выводит об этом сообщение.

Кнопка ищется методами компьютерного зрения по скриншоту экрана. Appium, UIAutomator и другие
автоматоры не используются: с устройством скрипт общается только стандартными командами `adb`
(`screencap`, `input tap`, `am`, `pm`).

## Требования

- Python 3.12+
- [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) (`adb`)
- Телефон с включённой отладкой по USB, авторизованный на этом компьютере (`adb devices` показывает `device`)

### Зависимости

| Пакет                    | Версия   | Назначение                                  |
|--------------------------|----------|---------------------------------------------|
| `opencv-python-headless` | 5.0.0.93 | декодирование скриншота, маски, контуры     |
| `numpy`                  | 2.5.3    | работа с изображением как с массивом        |

Для разработки (`requirements-dev.txt`) дополнительно нужны `pytest`, `ruff` и `mypy`.
Работа с `adb` написана на стандартной библиотеке (`subprocess`), отдельного пакета для неё не требуется.

## Установка

```bash
python3.12 -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt          # только для запуска
pip install -r requirements-dev.txt      # для запуска и тестов
```

Второй вариант: `pip install -e .[dev]`. Он дополнительно устанавливает консольную команду `green-button`.

## Запуск

```bash
python main.py com.example.app
# или
python -m green_button com.example.app
```

```
$ python main.py com.example.app
Green button found in com.example.app at (540, 1385), size 900x170, after 0.3 s. Tapped.

$ python main.py com.example.app
Green button not found in com.example.app within 10 s (12 screenshot(s) checked).
```

| Опция                 | Описание                                                                             |
|-----------------------|--------------------------------------------------------------------------------------|
| `package`             | имя пакета приложения, например `com.example.app`                                    |
| `-t`, `--timeout`     | сколько секунд ждать кнопку после запуска приложения (по умолчанию `10`)             |
| `-s`, `--serial`      | серийный номер устройства, если их подключено несколько (или `$ANDROID_SERIAL`)      |
| `--adb-path`          | путь к `adb`; по умолчанию ищется в `PATH`, `$ANDROID_HOME`, `$ANDROID_SDK_ROOT`     |
| `--no-restart`        | не делать `force-stop` перед запуском, просто вывести приложение на передний план    |
| `-v`, `--verbose`     | подробный лог в stderr: команды adb, каждая попытка поиска, найденные кандидаты      |

### Коды выхода

| Код   | Значение                                                                                |
|-------|-----------------------------------------------------------------------------------------|
| `0`   | кнопка найдена и нажата                                                                 |
| `1`   | за отведённое время кнопка не появилась                                                 |
| `2`   | неверные аргументы (например, некорректное имя пакета)                                  |
| `3`   | ошибка окружения: нет `adb`, нет или несколько устройств, приложение не установлено, не удалось запустить |
| `130` | прервано пользователем (Ctrl+C)                                                         |

Результат выводится в stdout, ошибки и логи — в stderr.

## Как это работает

1. `adb start-server`, `adb get-state`: проверяем, что устройство подключено и авторизовано.
2. `pm list packages <package>`: проверяем, что приложение установлено.
3. `input keyevent KEYCODE_WAKEUP`, `wm dismiss-keyguard`: будим экран и снимаем блокировку без пароля.
   Обе команды выполняются по возможности: на старых версиях Android их отсутствие не считается ошибкой.
4. `am force-stop <package>`: холодный старт, чтобы экран был в предсказуемом состоянии (отключается `--no-restart`).
5. `cmd package resolve-activity` находит launcher-активити, `am start -W` запускает её и ждёт первой отрисовки.
   Если `resolve-activity` недоступна (Android < 7), используется `monkey -p <package> -c LAUNCHER 1`.
6. Цикл ожидания длиной до `--timeout` секунд: `adb exec-out screencap -p` → поиск кнопок на PNG.
   Если кандидатов нет, повторяем через 0,5 с. Последняя проверка делается ровно в момент истечения таймаута.
   Попытка, начатая до дедлайна, доводится до конца, новая после дедлайна не начинается.
7. Если найдено несколько зелёных кнопок, выбирается самая крупная, и в её центр отправляется `input tap x y`.
   Координаты скриншота совпадают с координатами `input tap`, так что масштабирование не нужно.

## Алгоритм поиска зелёной кнопки

Реализация: `green_button/infrastructure/vision/green_button_detector.py`, пороги собраны в `DetectionSettings`.

1. **Маска зелёного.** Скриншот переводится в HSV, в маску попадают пиксели с оттенком
   H ∈ [35, 85] (70°–170°, от жёлто-зелёного до изумрудного), насыщенностью S ≥ 80 и яркостью V ≥ 60.
   Серые, белые, чёрные, бирюзовые (teal) и жёлтые пиксели в маску не попадают.
2. **Морфологическое закрытие** (эллипс 5×5) убирает мелкие разрывы, в том числе на сглаженных (anti-aliased) краях.
3. **Внешние контуры** (`RETR_EXTERNAL`): белый текст или иконка внутри кнопки не дробят её на части.
4. **Фильтры формы.** Каждый контур проверяется так:

| Фильтр                                        | Порог                    | Что отсекает                                   |
|-----------------------------------------------|--------------------------|------------------------------------------------|
| площадь относительно экрана                   | 0,2 % … 50 %             | иконки, точки, буквы; зелёный фон              |
| короткая сторона относительно ширины экрана   | ≥ 3 %                    | тонкие линии, подчёркивания, прогресс-бары     |
| соотношение сторон                            | ≤ 12 : 1                 | полосы и разделители                           |
| не во всю ширину экрана                       | —                        | тулбары, статус-бар, баннеры                   |
| extent: площадь / площадь bounding box        | ≥ 0,7 (у круга ≈ 0,785)  | треугольники, диагональные и сложные фигуры    |
| solidity: площадь / площадь выпуклой оболочки | ≥ 0,9                    | L-образные и «рваные» области, слитный текст   |
| заливка: доля зелёных пикселей внутри контура | ≥ 0,7                    | контурные (outlined) рамки, кольца, буквы «O»  |

Так распознаются прямоугольные, скруглённые, «таблеточные» (pill) и круглые (FAB) кнопки любого
оттенка зелёного на светлом и тёмном фоне.

## Архитектура

Слоистая архитектура: зависимости направлены только внутрь, к домену.
Прикладной слой описывает нужные ему интерфейсы (порты), инфраструктура их реализует.

```
green_button/
├── domain/                     # чистая модель, без I/O и сторонних библиотек
│   ├── models.py               #   PackageName (с валидацией), Point, BoundingBox, Button
│   ├── selection.py            #   правило выбора цели: самая крупная кнопка
│   └── errors.py               #   иерархия исключений
├── application/                # сценарий и порты
│   ├── ports.py                #   Protocol: Device, ButtonDetector, Clock
│   └── tap_green_button.py     #   TapGreenButtonUseCase: запуск → ожидание → нажатие
├── infrastructure/             # адаптеры к внешнему миру
│   ├── adb/                    #   AdbClient (subprocess), AdbDevice (реализует Device), поиск adb
│   ├── vision/                 #   OpenCvGreenButtonDetector (реализует ButtonDetector)
│   └── clock.py                #   SystemClock (реализует Clock)
├── presentation/
│   └── cli.py                  # argparse, форматирование результата, коды выхода
└── bootstrap.py                # composition root: собирает use case из конкретных адаптеров
```

```
presentation ──► application ──► domain
      │               ▲
      ▼               │ реализует порты
  bootstrap ──► infrastructure ──► domain
```

- Use case ничего не знает об `adb` и OpenCV: он работает с протоколами `Device`, `ButtonDetector`
  и `Clock`. Поэтому его логика (таймаут, опрос, выбор кнопки) тестируется без устройства и без реального времени.
- Время внедряется через порт `Clock`, так что тесты таймаута детерминированы и выполняются мгновенно.
- Ошибки инфраструктуры (`AdbError` и наследники) наследуются от доменного `DeviceError`,
  поэтому CLI обрабатывает их, не зная про adb.

## Тесты и проверки

```bash
pytest                                  # 101 тест, около 1 секунды
ruff check . && ruff format --check .
mypy --strict green_button tests main.py
```

| Файл                        | Что проверяется                                                                  |
|-----------------------------|-----------------------------------------------------------------------------------|
| `tests/test_detector.py`    | детектор на синтетических скриншотах: оттенки зелёного, круглые и pill-кнопки, тёмная тема; отказ на красных, синих, жёлтых и бирюзовых кнопках, тексте, рамках, кольцах, тулбарах, линиях, фоне |
| `tests/test_use_case.py`    | порядок действий, опрос до появления кнопки, таймаут, выбор самой крупной, `--no-restart` |
| `tests/test_adb_device.py`  | формирование adb-команд и разбор их вывода, fallback на `monkey`, ошибки запуска  |
| `tests/test_adb_client.py`  | вызов `subprocess`, `-s <serial>`, экранирование, таймауты, отсутствие `adb`      |
| `tests/test_cli.py`         | вывод, коды выхода, валидация аргументов                                         |
| `tests/test_end_to_end.py`  | use case с настоящим OpenCV-детектором: сплэш-экран → экран с красной и зелёной кнопками |

## Допущения и ограничения

- «Кнопка» определяется только визуально, как сплошная зелёная область подходящей формы. Без UI-иерархии
  нельзя отличить кнопку от декоративной зелёной плашки той же формы: такая плашка тоже будет считаться кнопкой.
- Контурные (outlined) и бледные пастельные зелёные кнопки (насыщенность меньше ~30 %) не считаются зелёными.
- Полноширинные зелёные элементы (тулбар, баннер, кнопка от края до края экрана) отбрасываются намеренно.
- Если окно защищено флагом `FLAG_SECURE`, `screencap` возвращает чёрный кадр, и кнопка не будет найдена.
- Экран, заблокированный PIN-кодом, паролем или графическим ключом, скрипт не разблокирует.
